# பங்களிப்பு

**மொழிகள்:** [English](Contributing.html) · **தமிழ்**

---

## அமைத்துக்கொள்ளுதல்

```bash
git clone https://github.com/bytamilan/nanayam.git
cd nanayam

nanayam prerequisites --auto              # அல்லது Go, Node, Docker-ஐ நீங்களே நிறுவுங்கள்
cd apps/org-console && pnpm install && cd ../..

make build
make test
```

புதிய clone-இல் `make test` பச்சையாக இருந்தால், உங்கள் சூழல் தயார்.

---

## Push செய்வதற்கு முன்

```bash
make validate
```

இது வடிவமைப்பு, vet, build, ஒவ்வொரு சோதனைத் தொகுப்பையும் இயக்குகிறது — CI இயக்கும் அதே சரிபார்ப்புகள். சிவப்பு build-க்காகக் காத்திருப்பதைவிட உள்ளூரில் இயக்குவது வேகமானது.

## களஞ்சிய அமைப்பு

```
nanayam/

├── config/               cryptogen மற்றும் configtx
├── docker/               Compose தொகுப்புகள்
├── k8s/                  Kubernetes manifests
├── scripts/              அமைவு மற்றும் நிறுவல் ஸ்கிரிப்ட்கள்

```

## பாணி

**Go.** நிலையான `gofmt`; `make fmt` அதைப் பயன்படுத்துகிறது. பிழைகளைச் சூழலுடன் சுற்றுங்கள்: `fmt.Errorf("read configtx source %s: %w", path, err)`. வெளியேற்றப்பட்ட அடையாளங்களுக்கு doc கருத்துகள் தேவை. `cmd/` கோப்புகளைக் கட்டளை வரையறை மற்றும் ஒருங்கிணைப்புக்கு மட்டும் வைத்திருங்கள்; உண்மையான தர்க்கம் `internal/`-க்கு உரியது.

**TypeScript.** சுற்றியுள்ள கோப்புடன் பொருந்துங்கள். Route handlers வெளிப்படையான நிலையுடன் `NextResponse.json` திருப்பித் தர வேண்டும். டோக்கனோ secret-ஓ பதில் body-க்கு ஒருபோதும் செல்லக்கூடாது.

**Shell.** மேலே `set -euo pipefail`. ஒவ்வொரு விரிவாக்கத்தையும் மேற்கோளிடுங்கள். ஒவ்வொரு ஸ்கிரிப்டும் `bash -n` மற்றும் warning நிலையில் shellcheck-ஐக் கடக்க வேண்டும்.

## Commit-கள்


**ஏன்** என்பதை body-இல் விளக்குங்கள், என்ன என்பதை மட்டுமல்ல. என்ன மாறியது என்பதை diff ஏற்கனவே காட்டுகிறது.

## Pull request-கள்

1. `main`-இலிருந்து கிளை பிரியுங்கள்.
2. சோதனைகளுடன் மாற்றத்தைச் செய்யுங்கள்.
3. `make validate` இயக்குங்கள்.
4. நடத்தை மாறியிருந்தால் ஆவணங்களைப் புதுப்பியுங்கள் — தமிழ்ப் பக்கம் உட்பட.
5. சிக்கலையும் அதை எப்படித் தீர்த்தீர்கள் என்பதையும் விவரித்து PR திறங்கள்.

ஆவணப்படுத்தப்பட்ட நடத்தையை மாற்றி, ஆவணங்களைப் பழையதாக விட்டுவைக்கும் மாற்றம் முடிக்கப்படவில்லை.

## சோதனைகள்

ஒவ்வொரு பிழைத் திருத்தத்துடனும், அது இல்லாமல் தோல்வியடையும் சோதனை வர வேண்டும். மரபுகளுக்கு [சோதனை](Testing-ta.html) பார்க்கவும் — சுருக்கமாக:

- நேரடியாக எழுதப்பட்ட முழுப் பாதைகள் வேண்டாம். `t.TempDir()` அல்லது `repoRoot(t)` பயன்படுத்துங்கள்.
- சோதனைகளுக்கு அவை உறுதி செய்யும் நடத்தையின் பெயரை வையுங்கள்.
- ஒரு உறுதிப்பாடு ஏன் முக்கியம் என்று குறிப்பிடுங்கள், அது என்ன செய்கிறது என்பதல்ல.
- மகிழ்ச்சியான பாதையை மட்டுமல்ல, பிழைப் பாதைகளையும் உள்ளடக்குங்கள்.

## ஆவணங்கள்

விக்கி `docs/wiki/`-இல் வாழ்கிறது; `main`-க்கு push செய்யும்போது GitHub Wiki-க்குத் தானாக வெளியிடப்படுகிறது.

**பக்கங்கள் இணையாக வருகின்றன.** `Architecture.md` மற்றும் `Architecture-ta.md` — ஒரே பக்கம், ஆங்கிலத்திலும் தமிழிலும். ஒன்றை மாற்றும்போது மற்றொன்றையும் மாற்றுங்கள். தமிழில் எழுத முடியாவிட்டால், PR-இல் அதைச் சொல்லுங்கள்; யாராவது உதவுவார்கள் — அமைதியாகப் பழையதாகிப்போன தமிழ்ப் பக்கம், வெளிப்படையாக இல்லாத பக்கத்தைவிட மோசமானது.

இரு பதிப்புகளும் மேலே ஒன்றையொன்று இணைக்கின்றன:

```markdown
**மொழிகள்:** [English](Page-Name) · **தமிழ்**
```

வரைபடங்கள் ```mermaid தொகுதிகளில் [Mermaid](https://mermaid.js.org/) வடிவில் உள்ளன; GitHub அவற்றை நேரடியாகக் காட்டுகிறது.

## புதிய விக்கி பக்கம் சேர்த்தல்

1. `docs/wiki/`-இல் `New-Page.md` மற்றும் `New-Page-ta.md` எழுதுங்கள்.
2. இரண்டையும் `_Sidebar.md`-இல் சேருங்கள்.
3. முக்கிய அட்டவணையில் இடம் பெற வேண்டுமெனில் `Home.md` மற்றும் `Home-ta.md`-இலிருந்து இணையுங்கள்.
4. ஒவ்வொன்றின் மேலும் மற்றொன்றை இணையுங்கள்.

## பிழைகளைத் தெரிவித்தல்

நீங்கள் என்ன இயக்கினீர்கள், என்ன எதிர்பார்த்தீர்கள், முழுப் பிழை, உங்கள் பதிப்புகள் (`nanayam version`, `docker --version`, `go version`, OS மற்றும் architecture) — இவற்றைச் சேர்க்கவும். மீண்டும் நிகழ்த்திப் பார்க்கக்கூடிய ஒரு அறிக்கை, முடியாத பலவற்றைவிட மதிப்புமிக்கது.
